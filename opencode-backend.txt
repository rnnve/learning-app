1. ARCHITECTURE DECISIONS (ALREADY MADE; IMPLEMENT AS WRITTEN)
--------------------------------------------------------------------------------
 - Runtime/framework: Bun + ElysiaJS. Routes validated with Elysia's `t`
   (TypeBox). TypeBox schemas are the single source of truth for: request
   validation, response typing, OpenAPI generation, AND AI-output validation
   (via TypeBox `Value.Check`/`Value.Errors`) and Gemini JSON schemas.
 - Database: PostgreSQL 16+ with Drizzle ORM + drizzle-kit migrations. JSONB
   for generated material content and preferences. (Verify Drizzle's current
   Bun-compatible Postgres driver in its docs; `postgres` (porsager) or
   `Bun.sql` are both acceptable. Pick one and keep it consistent.)
 - Job queue: a Postgres-backed `jobs` table processed by an in-process worker
   loop using `SELECT ... FOR UPDATE SKIP LOCKED`, leases, heartbeats, retries
   with exponential backoff. No Redis. The worker runs inside the API process
   (configurable via WORKER_ENABLED so it can later be split out).
 - File storage: a `StorageProvider` interface with a LocalDiskStorage
   implementation writing to a Docker volume (STORAGE_DIR). Storage keys are
   server-generated (`users/<userId>/sources/<sourceId>/<uuid>.<ext>`); the
   client's filename is NEVER used in a path. An S3-compatible implementation
   may be added later behind the same interface; do not build it now.
 - Auth: guest accounts (zero-friction for students) that can be upgraded in
   place to email+password accounts. Short-lived JWT access tokens (15 min) +
   opaque rotating refresh tokens (30 days) stored hashed, with reuse
   detection. Passwords hashed with Bun.password (argon2id).
 - AI providers behind interfaces:
     ExtractionProvider  (image -> structured transcription)  = Nemotron
     GenerationProvider  (text -> structured study content)   = Gemini
   Business logic depends only on the interfaces. Providers are selected and
   configured by env. A FakeProvider exists for tests and (flagged) dev only.
 - Retrieval for large sources: no embeddings in v1. Use chunking + in-process
   BM25 scoring over the chunks of ONE source, with Thai tokenization via
   Intl.Segmenter('th', { granularity: 'word' }) (verify it works in the
   Bun runtime; if ICU data is missing in the Docker image, fix the image).
 - Chat is synchronous JSON (no streaming) in v1. Material generation and
   source processing are asynchronous jobs polled by the client.
 - Language: system messages/prompts in English for instruction-following
   quality; OUTPUT language is governed by user preference (default Thai).
 - Privacy: students' content is sent to third-party AI providers. The user
   must record consent (PUT /v1/me/consent) before uploading or generating.
   Without it: 403 CONSENT_REQUIRED. (Product owner must have the consent text
   and age/guardian handling reviewed against Thailand's PDPA; note this in
   docs/PRIVACY-NOTES.md. This is not legal advice.)

3. SHARED API CONTRACT v1  (IDENTICAL IN BOTH INSTRUCTION FILES)
--------------------------------------------------------------------------------
3.1 Conventions
 - Base path: /v1. JSON, UTF-8, camelCase. Timestamps: ISO-8601 UTC strings.
   IDs: UUID strings.
 - Auth header on every endpoint except those marked PUBLIC:
       Authorization: Bearer <accessToken>
 - Optional request headers: Accept-Language (th|en; only picks the language of
   the human-readable `message` in errors), X-Request-Id (echoed back).
 - Idempotency-Key (UUID, client generated) is REQUIRED on: POST /v1/sources,
   POST /v1/materials, POST /v1/conversations/:id/messages. Same key + same
   body => the original response is replayed. Same key + different body =>
   422 IDEMPOTENCY_KEY_REUSED. Same key while the first call is in flight =>
   409 REQUEST_IN_PROGRESS. Keys are kept 24 h.
 - Pagination (list endpoints): query `limit` (1..50, default 20) and `cursor`
   (opaque string). Response: { "items": [...], "nextCursor": string | null }.
   Lists are ordered newest first unless stated.
 - Success with no body: 204.

3.2 Error format (every non-2xx response)
   { "error": { "code": "STRING_CODE", "message": "human readable",
                "retryable": boolean, "requestId": "uuid",
                "details": { ... } | null } }
 `Job.error` and `Source.error` use the same object WITHOUT `requestId`.
 The frontend maps `code` to localized Thai/English text; `message` is only a
 fallback. Never put stack traces or provider internals in errors.

  POST   /v1/conversations     body { title?, sourceId?: string|null } -> 201 Conversation
  GET    /v1/conversations     ?sourceId&limit&cursor -> 200 { items, nextCursor }
  GET    /v1/conversations/:id -> 200 Conversation
  PATCH  /v1/conversations/:id body { title } -> 200 Conversation

        -> 200 { items: Message[] (newest first), nextCursor }
  POST   /v1/conversations/:id/messages   Idempotency-Key required.
        body { content: string(1..4000), clientMessageId: uuid,
               language?: ContentLanguage, level?: Level|"auto" }
        -> 201 { userMessage: Message, assistantMessage: Message }
        SYNCHRONOUS (client timeout 60 s). On AI failure the user message is
        NOT persisted; the client keeps the text and may retry with the same
        Idempotency-Key. Errors: AI_* codes, 429, 403 CONSENT_REQUIRED.
        A conversation with sourceId must reference a ready/partial source.
        Title: if the conversation title is empty, the server sets it to the
        first 40 chars of the first user message (no AI call).

  Study
  POST   /v1/study-sessions    body { materialId, mode:"flashcards"|"quiz" } -> 201 StudySession
        (mode must match the material type)
  GET    /v1/study-sessions    ?materialId&limit&cursor -> 200 { items, nextCursor }
  GET    /v1/study-sessions/:id -> 200 { session: StudySession,
                                  answers: [{ itemId, verdict|null,
                                  rating|null, answeredAt }] }
  POST   /v1/study-sessions/:id/answers
        flashcards: body { itemId, rating: CardRating } -> 200 AnswerResult
        quiz:       body { itemId, choiceId?: string, text?: string }
                    -> 200 AnswerResult
        Multiple choice/true-false are graded deterministically. short_answer
        is graded first against acceptedAnswers (normalized); if no match, by
        Gemini with the model answer + source context (<= 30 s). An item is
        answered once per session; repeating returns the stored result.
  POST   /v1/study-sessions/:id/complete -> 200 StudySession (score computed:
        correct=1, partially_correct=0.5, incorrect=0 over itemsTotal)

3.6 Limits (defaults; configurable in backend env, exposed in /v1/meta)
  image: <= 10 MB each, <= 10 images per source, JPEG/PNG/WebP only
         (the app converts HEIC and downsizes to <= 2048 px long edge, JPEG q~0.85)
  document: <= 25 MB; PDF <= 100 pages; DOCX/TXT extracted text <= 1,500,000 chars
  OCR cap for scanned PDFs: first 40 pages by default; further pages are
         skipped with an ExtractionWarning code "OCR_PAGE_CAP".
  chat message <= 4000 chars; generations/day = 30; chat messages/day = 200
  rate limits: 120 req/min/IP general; 10 req/min/IP on /v1/auth/*

3.7 Polling guidance (frontend)
  Poll GET /v1/jobs/:id every 1.5 s, backing off to 4 s after 30 s; stop on
  succeeded/failed/canceled. After source_processing succeeds, fetch the source
  and SHOW extraction status before offering generation.

6. AUTH, AUTHORIZATION, SECURITY
--------------------------------------------------------------------------------
 - Guest: POST /auth/guest creates user (is_guest=true, display_name default
   "นักเรียน"). Register while holding a guest token upgrades that user:
   set email + password_hash, is_guest=false; keep all data. Email already
   used -> 409 EMAIL_TAKEN. Normalize emails (trim, lowercase). Use constant-
   time-ish behavior and the same error for unknown email vs wrong password.
 - Access token: JWT (HS256, JWT_SECRET) claims { sub, iat, exp, jti }.
   Expired -> TOKEN_EXPIRED; otherwise invalid -> UNAUTHENTICATED.
 - Refresh tokens: 32+ random bytes base64url; store sha256 only. Rotate on
   every refresh. If a revoked token is presented, revoke the whole family and
   return REFRESH_TOKEN_REUSED.
 - Auth plugin derives `user` for protected routes; protected route groups must
   fail closed. Add an integration test that walks the OpenAPI route list and
   asserts every non-PUBLIC route returns 401 without a token.
 - Ownership: services take userId as a required argument and include it in
   every WHERE. Add cross-user tests for every resource type (sources, files,
   text, materials, jobs, conversations, messages, study sessions).
 - Consent gate: upload, material generation, chat message, and short-answer
   grading require users.consent_version == CONSENT_VERSION else
   403 CONSENT_REQUIRED.
 - Security headers (X-Content-Type-Options: nosniff, Referrer-Policy:
   no-referrer, etc.); strict CORS allow-list (none by default); body size cap
   via Bun `maxRequestBodySize` (documented limit * maxFiles + overhead);
   stream/measure uploads, reject early.
 - Logging: structured JSON logs with requestId, userId, route, status,
   duration. NEVER log request bodies, file content, extracted text, prompts,
   model outputs, tokens, or keys. Redact Authorization.
 - Rate limiting: elysia-rate-limit (or small in-memory implementation) per IP,
   stricter on /v1/auth/*, and per-user daily quotas (usage_counters). Return
   429 with Retry-After header and details.retryAfterSec. Document that
   in-memory limits are per-instance (fine for the single-container v1).
 - Prompt-injection posture: source text and chat history are UNTRUSTED DATA.
   Prompts instruct the model to treat them as content, not instructions.
   Model output never triggers tools or side effects other than being stored.

7. UPLOADS, FORMATS, VALIDATION, DOCUMENT PROCESSING
--------------------------------------------------------------------------------
7.1 Supported formats (and ONLY these)
  Images: JPEG, PNG, WebP.      (HEIC/HEIF/GIF/TIFF/BMP -> 415 with a message
                                  telling the user to convert; the app converts.)
  Documents: TXT (UTF-8; also detect UTF-16 BOM and Windows-874/TIS-620 Thai
  legacy encodings via TextDecoder('windows-874') when UTF-8 decoding yields
  replacement characters), PDF, DOCX.
  NOT supported in v1 (return 415, mention in docs): DOC, PPT/PPTX, XLS/XLSX,
  RTF, ODT, EPUB, Markdown (treat .md as unsupported unless you add it with a
  sniff test; optional), HTML. Add only with a reliable secure extractor.

7.2 Validation order (reject early, never trust extension or client MIME)
  1. Auth + consent + idempotency.
  2. Count files (TOO_MANY_FILES), mixing rules, per-file size limits
     (FILE_TOO_LARGE), empty files.
  3. Sniff real type from magic bytes (src/processing/sniff.ts): JPEG FFD8FF,
     PNG 89504E47..., WebP RIFF....WEBP, PDF %PDF-, DOCX = ZIP (PK\x03\x04) AND
     contains [Content_Types].xml and word/document.xml. TXT: no NUL bytes,
     decodes as text. Claimed MIME/extension must be consistent with the sniffed
     type else 415 UNSUPPORTED_MEDIA_TYPE.
  4. Store originals to a temp area; create source (status queued) + job in one
     DB transaction; respond 202. All heavy work happens in the worker.
  5. In the worker (stage "validating"): deeper checks per kind:
     - Images: decode with sharp; reject undecodable (FILE_CORRUPT); cap pixel
       count (e.g. <= 50 MP) to prevent decompression bombs.
     - PDF: parse in the sandbox (7.4); encrypted -> PDF_ENCRYPTED; page count
       > MAX_PDF_PAGES -> TOO_MANY_PAGES.
     - DOCX: zip limits (<= 2000 entries, total uncompressed <= 100 MB,
       per-entry ratio sanity check) before parsing; password-protected /
       invalid -> FILE_CORRUPT.

7.3 Processing per kind  (set Extraction.method accordingly)
  IMAGES (kind=images): for each photo: normalize with sharp (auto-orient,
    strip EXIF/GPS, convert to JPEG q85, max 2048 px long edge) and store the
    normalized copy as the served file. Send each page to Nemotron (Section 8.2)
    sequentially or with small concurrency (2). One page = one `page`.
    method = vision_ocr.
  TXT: decode, normalize newlines, no model call. method = direct_text.
  DOCX: extract text with `mammoth` (raw text / structure-preserving; verify it
    runs under Bun) inside the sandbox. Embedded images are NOT analyzed in v1:
    if the package contains word/media/*, add warning code
    "EMBEDDED_IMAGES_NOT_ANALYZED" (page null). method = direct_text.
  PDF: for each page extract the text layer (use `unpdf`/pdfjs-dist in the
    sandbox). Decide per page: if the text layer has fewer than 25 meaningful
    characters (after trimming) the page is treated as image-only. If ALL pages
    are image-only => scanned PDF => OCR route. If SOME pages are image-only =>
    hybrid. OCR route: render page to PNG/JPEG with `pdftoppm` (poppler-utils;
    spawn with an args array, never a shell; 150 DPI; timeout per page), then
    send to Nemotron exactly like a photo. OCR at most OCR_PAGE_CAP pages;
    skipped pages -> warning "OCR_PAGE_CAP" and status partial.
    Embedded raster images inside text pages are NOT extracted/analyzed in v1:
    warning "EMBEDDED_IMAGES_NOT_ANALYZED". (Document this in LIMITATIONS.md.)
    method = direct_text | vision_ocr | hybrid.
  Never call Nemotron for text-extractable documents.

7.4 Sandbox for parsers (src/processing/sandbox.ts)
  Run PDF and DOCX parsing in a Bun Worker (or `Bun.spawn` of a small script)
  with a hard timeout (default 60 s, terminate on expiry) and bounded output
  size. A crashing/hanging parser must fail only that job (FILE_CORRUPT or
  EXTRACTION_FAILED), never the API process. Subprocesses use argument arrays
  only. Temp files go in a per-job temp dir that is always cleaned in `finally`.

7.5 Post-extraction
  - Normalize text (NFC, collapse excessive blank lines, strip control chars).
    Do NOT strip Thai combining marks. Do NOT insert/remove spaces inside Thai.
  - Detect language heuristically: ratio of Thai-block chars (U+0E00-0E7F) to
    letters: >0.6 th, <0.05 en, else mixed; too little text -> unknown.
  - If total chars < 20 meaningful characters -> job fails NO_EXTRACTABLE_CONTENT
    (or IMAGE_UNREADABLE for images where quality is "unreadable").
  - Cap total at MAX_EXTRACTED_CHARS (truncate at a page boundary, warning
    "TEXT_TRUNCATED", status partial).
  - Chunk (Section 9.2), persist chunks, compute source.status:
      ready   - all pages extracted, quality good/fair
      partial - some pages failed/skipped OR overall quality "poor"
      failed  - nothing usable
  - Extraction.quality for OCR = the worst page quality reported by the model
    (poor if > 30% of pages are poor). For direct text = "good".
  - Delete temp files; keep originals/normalized files for preview.

8.6 Fixture/fake provider and "never pretend" rule

    text begins with "[ตัวอย่างจำลอง / FIXTURE]". They are stored with
    generatedBy.mode = "fixture", provider "fake", model "fixture". /v1/meta
    reports ai.*="fixture". The frontend shows a persistent banner for fixture
    mode and materials with mode fixture. Fixture extraction must be a fixed,
    labelled string, never derived from the image to look real.
  - Unit/integration tests inject FakeProvider instances programmatically.

9. PROCESSING PIPELINE, JOBS, LARGE DOCUMENTS
--------------------------------------------------------------------------------
9.1 Worker (src/worker/loop.ts)
  - Poll every ~1 s (and immediately after enqueue): claim up to
    WORKER_CONCURRENCY jobs with `FOR UPDATE SKIP LOCKED` where status='queued'
    AND run_after <= now(); set running, locked_by, lease (60 s) and heartbeat
    every 20 s. On boot, requeue jobs whose lease expired.
  - Handlers update stage/progress/detail as they go (contract 3.4 stage names).
    Progress for OCR: 20 + 60 * pagesDone/pagesTotal; chunking 85; finalizing 95.
  - Retry: retryable AppErrors -> attempt++ and run_after = now + backoff
    (10 s, 40 s) until max_attempts (3), then failed. Non-retryable -> failed
    immediately. Persist ErrorBody on failure; mirror onto sources.error.
  - Cancel: check a cancel flag between pages/stages; set status canceled.
  - Idempotent handlers: re-running a job must not duplicate chunks or materials
    (delete-and-reinsert chunks for the source inside a transaction; materials
    are created only in the final "saving" step inside a transaction together
    with the job result).
  - Per-call timeouts via AbortSignal (NEMOTRON_TIMEOUT_MS, GEMINI_TIMEOUT_MS).
    Per-job overall deadline (default 10 min) -> failed with AI_TIMEOUT.

9.2 Chunking (src/processing/chunker.ts)  - pure and unit tested
  - Work per page. Split on blank lines/headings first, then sentence-ish
    boundaries (for Thai use Intl.Segmenter('th', {granularity:'sentence'}) with
    fallback to word segmenter boundaries; never cut inside a word or between a
    base character and its combining marks), then hard-split as a last resort.
  - Target CHUNK_TARGET_CHARS (default 3500) with CHUNK_OVERLAP_CHARS (default
    300) overlap between consecutive chunks of the same page flow. Each chunk
    records idx (global, ascending), page (start page), text, char_count.
    A chunk may span a page boundary; page = first page. Keep headings attached
    to the following text.

9.3 Generation strategy (src/ai/pipeline/generate.ts)
  1. preparing_context: load chunks (apply options.pageRange by chunk page).
     If a pageRange selects nothing -> 422 VALIDATION_ERROR at request time.
  2. DIRECT mode when total chars <= DIRECT_CONTEXT_CHAR_BUDGET (default 60,000;
     tune after verifying the model's context window in docs/PROVIDERS.md):
     one request with all chunks inside the SOURCE delimiter.
  3. MAP-REDUCE mode otherwise:
     - Group consecutive chunks into sections <= ~DIRECT_CONTEXT_CHAR_BUDGET/2.
     - SUMMARY: map = per-section "notes" (key facts + sourceRefs, JSON), reduce
       = final SummaryContent produced ONLY from the notes, preserving refs.
     - FLASHCARDS/QUIZ: allocate the requested count proportionally across
       sections (min 1 per section when count allows), generate per section, then
       merge, de-duplicate (normalized-text similarity, e.g. Jaccard on Thai-
       segmented tokens > 0.8), and trim/reorder to the requested count with
       broad coverage.
     - Cap concurrency of section calls at 2; checkpoint partial progress so a
       retry does not redo finished sections within the same job attempt.
     - Hard cap: if sections > 25, ask the user to choose a pageRange
       (fail fast with VALIDATION_ERROR details.suggestPageRange=true).
  4. validating_output + saving: Section 9.4, then create the Material row.
  5. Quota: increment generations/day only when a job is created (not on
     idempotent replay/dedupe hit); do not refund on failure in v1 (document).

9.4 Post-processing (src/ai/pipeline/postprocess.ts) - pure and unit tested
  - Resolve each model sourceRef: chunkId must exist in the source (and within
    the selected range); drop unknown ids. Fill `page` from the chunk. Keep
    `quote` only if after whitespace normalization it is a substring of the chunk
    text (<= 200 chars); otherwise set quote=null. Never invent refs.
  - Assign stable ids: cards "card-1..n", questions "q-1..n".
  - Quiz integrity: exactly one correct choice that exists; ids unique; true_false
    has exactly the two canonical choices; short_answer has >=1 acceptedAnswers;
    drop invalid questions and, if fewer than 60% of the requested count remain,
    fail with AI_OUTPUT_INVALID. Shuffle MC choice order deterministically
    (seeded) so the correct answer position is not biased, after validating.
  - Flashcards: trim whitespace, drop empty/over-long (> 400 chars front,
    > 800 back) cards, de-duplicate.
  - Summary: require non-empty overview; drop empty keyPoints/sections.
  - Title: if the client did not supply one, build "<type label> - <source title>"
    (Thai labels: สรุป / แฟลชการ์ด / แบบทดสอบ).
  - Record generatedBy {provider, model, promptVersion, mode} and options.

10. CHAT AND STUDY SERVICES
--------------------------------------------------------------------------------
10.1 Chat (POST /v1/conversations/:id/messages)
  - Order: auth -> consent -> idempotency -> quota -> load conversation (owned)
    -> check source ready/partial.
  - Context: last 12 messages (trim oldest to fit ~12,000 chars of history).
  - If conversation.source_id: retrieve top 6 chunks for the user message with
    BM25 over that source's chunks using Intl.Segmenter('th') tokens (lowercase
    Latin, drop punctuation, small Thai/English stopword lists, simple
    prefix-aware match for Latin). Always include chunk c0's heading context if
    the source is short. If total source <= 20,000 chars, send the whole source
    instead. Pass retrieved chunks in the SOURCE delimiter with ids.
  - Call Gemini with system prompt + CHAT task block + history + message;
    validate with chat schema; post-process citations like 9.4 (drop unknown
    chunk ids; quotes verified).
  - Persist user + assistant messages in ONE transaction only after a valid AI
    response. Update conversation.updated_at. Increment chat quota.
  - Synchronous; overall timeout 60 s -> AI_TIMEOUT.
10.2 Study sessions
  - Create: material must be owned and match mode. itemsTotal = cards/questions.
  - Flashcard answer: upsert card_progress with the Leitner function; return
    nextDueAt. Quiz answer: grade (MC/TF deterministic; short_answer via
    normalized match against acceptedAnswers (NFC, trim, lowercase Latin, strip
    punctuation/whitespace), else Gemini grading task 8.5.5 with 30 s timeout;
    if grading AI fails, return the relevant AI_* error and do NOT record the
    answer so the student can retry).
  - complete: compute score; idempotent; abandoned active sessions older than 7
    days may be auto-completed lazily on read (optional).

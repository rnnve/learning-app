   preferences). HTTP: Axios with a typed client and interceptors.
 - Auth: guest-first. On first launch (after onboarding consent) create a guest
   account so the student can start immediately; offer "save my progress" ->

   token in expo-secure-store.
 - i18n: i18next + react-i18next + expo-localization. The default UI language
   is ALWAYS Thai, whatever the device locale. English is offered on the
   language screen and in Settings; persist the choice locally (AsyncStorage or
   SecureStore) and sync it to preferences.uiLanguage on the server.
 - Glass effects: purely decorative progressive enhancement (Section 12).
 - Types: hand-written typed API layer from the contract in Section 3
   (src/api/types.ts). If the backend is running, the optional script
   `bun run gen:api` may generate types from /openapi.json via openapi-typescript
   for CROSS-CHECKING only; the committed hand-written types are authoritative.

3. SHARED API CONTRACT v1  (IDENTICAL IN BOTH INSTRUCTION FILES)
--------------------------------------------------------------------------------
3.1 Conventions
 - Base path: /v1. JSON, UTF-8, camelCase. Timestamps: ISO-8601 UTC strings.
   IDs: UUID strings.
 - Auth header on every endpoint except those marked PUBLIC:
       Authorization: Bearer <accessToken>
 - Optional request headers: Accept-Language (th|en; only picks the language of
   the human-readable `message` in errors), X-Request-Id (echoed back).
 - Idempotency-Key (UUID, client generated) is REQUIRED on: POST /v1/sources,
   POST /v1/materials, POST /v1/conversations/:id/messages. Same key + same
   body => the original response is replayed. Same key + different body =>
   422 IDEMPOTENCY_KEY_REUSED. Same key while the first call is in flight =>
   409 REQUEST_IN_PROGRESS. Keys are kept 24 h.
 - Pagination (list endpoints): query `limit` (1..50, default 20) and `cursor`
   (opaque string). Response: { "items": [...], "nextCursor": string | null }.
   Lists are ordered newest first unless stated.
 - Success with no body: 204.

3.2 Error format (every non-2xx response)
   { "error": { "code": "STRING_CODE", "message": "human readable",
                "retryable": boolean, "requestId": "uuid",
                "details": { ... } | null } }
 `Job.error` and `Source.error` use the same object WITHOUT `requestId`.
 The frontend maps `code` to localized Thai/English text; `message` is only a
 fallback. Never put stack traces or provider internals in errors.

 ExtractionWarning { code: string, message: string, page: number|null }

                pagesFailed: number[], warnings: ExtractionWarning[] }

                stage: string|null, progress: number /*0..100*/,
                detail: { page?: number, pagesTotal?: number } | null,
                attempt: number, error: ErrorBody|null,
                result: { sourceId?: string, materialId?: string } | null,
                createdAt, startedAt: string|null, finishedAt: string|null }

                              ocr, chunking, finalizing

                content: SummaryContent | FlashcardsContent | QuizContent,
                options: object, isSaved: boolean, generatedBy: GeneratedBy,

   appear in history/library; "Saved" is the starred subset.
 Text fields in content are PLAIN TEXT with line breaks. No LaTeX, no HTML.
 Math is written in readable Unicode (x², √(a+b), ½, π, →, ≤).
 Every content object has `sourceRefs` arrays where noted; they may be empty.

3.5 Endpoints
 PUBLIC
  GET  /health                 -> 200 { status:"ok", version, uptimeSec }
  GET  /ready                  -> 200|503 { status:"ready"|"not_ready",
                                  checks:{ database, storage, migrations:
                                  "ok"|"fail", nemotron, gemini:
                                  "configured"|"not_configured" } }
        (AI config never makes /ready fail; DB/storage/migrations do.)
  GET  /v1/meta                -> 200 { apiVersion:"1", promptVersion,
        limits:{ maxImageBytes, maxDocumentBytes, maxImagesPerSource,
                 maxPdfPages, maxChatMessageChars, maxGenerationsPerDay,
                 maxChatMessagesPerDay },
        supported:{ imageMimeTypes:["image/jpeg","image/png","image/webp"],
                    documentMimeTypes:[ "text/plain","application/pdf",
          "application/vnd.openxmlformats-officedocument.wordprocessingml.document"] },
        ai:{ extraction:"live"|"fixture"|"disabled",
             generation:"live"|"fixture"|"disabled" },
        consentVersion }
  POST /v1/auth/guest          body {} -> 201 AuthResponse
  POST /v1/auth/register       body { email, password(8..128), displayName? }
        -> 201 AuthResponse. If a guest access token is sent, the guest is
        UPGRADED IN PLACE (all data kept, isGuest=false). Else new user.
  POST /v1/auth/login          body { email, password } -> 200 AuthResponse
  POST /v1/auth/refresh        body { refreshToken } -> 200 { tokens }
        (rotation: old refresh token is invalidated)
  POST /v1/auth/logout         body { refreshToken } -> 204

 AUTHENTICATED
  GET    /v1/me                -> 200 User
  PATCH  /v1/me                body { displayName?, preferences?: Partial<Preferences> } -> 200 User
  PUT    /v1/me/consent        body { aiProcessing: true, version } -> 200 User
  DELETE /v1/me                body { confirm: "DELETE" } -> 204 (hard-deletes
                                everything: db rows + stored files)
  GET    /v1/home              -> 200 { stats:{ sources, materials,
                                  sessionsLast7Days }, activeJobs: Job[],
                                  recentSources: Source[] (max 5),
                                  recentMaterials: Material[] (max 5, no
                                  `content` -> see MaterialSummary) }
        MaterialSummary = Material without `content`, plus
        `itemCount: number` (cards/questions/keyPoints).

  Sources
  POST   /v1/sources           multipart/form-data, Idempotency-Key required.
        fields: files (repeatable file part), title? (string<=120),
                language? ("th"|"en"; hint only)
        rules: either 1..maxImagesPerSource image files (kind=images), OR
        exactly one TXT/PDF/DOCX. Mixed -> 422 VALIDATION_ERROR.
        -> 202 { source: Source (status "queued"), job: Job } + Location header
  GET    /v1/sources           ?status&kind&q(title search)&limit&cursor
                               -> 200 { items: Source[], nextCursor }
  GET    /v1/sources/:id       -> 200 Source
  PATCH  /v1/sources/:id       body { title } -> 200 Source
  GET    /v1/sources/:id/files/:index  -> original file bytes (auth required;
                               index 0-based; images re-encoded JPEG/PNG/WebP;
                               documents original) with correct Content-Type,
                               Content-Disposition: inline
  GET    /v1/sources/:id/text  ?limit&cursor (chunks in ascending order)
                               -> 200 { items: SourceChunk[], nextCursor }
        409 SOURCE_NOT_READY if status queued/processing/failed.
  POST   /v1/sources/:id/retry -> 202 { source, job }  (only if status failed
                               or partial; re-runs processing)
  DELETE /v1/sources/:id       ?keepMaterials=false -> 204. Deletes files,
        chunks, and (default) all derived materials, conversations about it,
        and their study sessions. keepMaterials=true keeps materials but sets
        their sourceId to null and strips sourceRefs quotes (chunk ids remain
        meaningless -> frontend hides source links when sourceId is null).

  Materials
  POST   /v1/materials         Idempotency-Key required. body:
        { type: MaterialType, sourceId: string, title?: string,
          options: {
            language?: ContentLanguage (default: user preference),
            level?: Level|"auto" (default: user preference),
            pageRange?: { from: number, to: number } | null,
            // summary:    length: "short"|"medium"|"detailed" (default medium)
            // flashcards: count: 5..50 (default 15)
            // quiz:       count: 3..30 (default 10),
            //             difficulty: Difficulty (default mixed),
            //             questionTypes: QuestionType[] (default all three)
          } }
        -> 202 { job: Job }. Errors: 409 SOURCE_NOT_READY, 403 CONSENT_REQUIRED,
        429 QUOTA_EXCEEDED, 503 AI_NOT_CONFIGURED.
        The server de-duplicates: an identical request (same user, source,
        type, normalized options) whose job is queued/running returns that
        existing job.
  GET    /v1/materials         ?type&sourceId&saved(true|false)&q&limit&cursor
                               -> 200 { items: MaterialSummary[], nextCursor }
  GET    /v1/materials/:id     -> 200 Material
  PATCH  /v1/materials/:id     body { title?, isSaved? } -> 200 Material
  DELETE /v1/materials/:id     -> 204
  GET    /v1/materials/:id/flashcard-progress  (flashcards only)
                               -> 200 { items:[{ cardId, dueAt, box:1..5,
                                  lastRating: CardRating|null }] }
        cards never reviewed are returned with dueAt = now, box 1.

  Jobs
  GET    /v1/jobs/:id          -> 200 Job
  GET    /v1/jobs              ?active=true -> 200 { items: Job[] }
  POST   /v1/jobs/:id/retry    -> 202 Job (only status failed AND
                               error.retryable true; else 409 JOB_NOT_RETRYABLE)
  POST   /v1/jobs/:id/cancel   -> 200 Job (queued/running only)

  Chat
  POST   /v1/conversations     body { title?, sourceId?: string|null } -> 201 Conversation
  GET    /v1/conversations     ?sourceId&limit&cursor -> 200 { items, nextCursor }
  GET    /v1/conversations/:id -> 200 Conversation
  PATCH  /v1/conversations/:id body { title } -> 200 Conversation
  DELETE /v1/conversations/:id -> 204
  GET    /v1/conversations/:id/messages ?limit&cursor
        -> 200 { items: Message[] (newest first), nextCursor }
  POST   /v1/conversations/:id/messages   Idempotency-Key required.
        body { content: string(1..4000), clientMessageId: uuid,
               language?: ContentLanguage, level?: Level|"auto" }
        -> 201 { userMessage: Message, assistantMessage: Message }
        SYNCHRONOUS (client timeout 60 s). On AI failure the user message is
        NOT persisted; the client keeps the text and may retry with the same
        Idempotency-Key. Errors: AI_* codes, 429, 403 CONSENT_REQUIRED.
        A conversation with sourceId must reference a ready/partial source.
        Title: if the conversation title is empty, the server sets it to the
        first 40 chars of the first user message (no AI call).

  Study
  POST   /v1/study-sessions    body { materialId, mode:"flashcards"|"quiz" } -> 201 StudySession
        (mode must match the material type)
  GET    /v1/study-sessions    ?materialId&limit&cursor -> 200 { items, nextCursor }
  GET    /v1/study-sessions/:id -> 200 { session: StudySession,
                                  answers: [{ itemId, verdict|null,
                                  rating|null, answeredAt }] }
  POST   /v1/study-sessions/:id/answers
        flashcards: body { itemId, rating: CardRating } -> 200 AnswerResult
        quiz:       body { itemId, choiceId?: string, text?: string }
                    -> 200 AnswerResult
        Multiple choice/true-false are graded deterministically. short_answer
        is graded first against acceptedAnswers (normalized); if no match, by
        Gemini with the model answer + source context (<= 30 s). An item is
        answered once per session; repeating returns the stored result.
  POST   /v1/study-sessions/:id/complete -> 200 StudySession (score computed:
        correct=1, partially_correct=0.5, incorrect=0 over itemsTotal)

3.6 Limits (defaults; configurable in backend env, exposed in /v1/meta)
  image: <= 10 MB each, <= 10 images per source, JPEG/PNG/WebP only
         (the app converts HEIC and downsizes to <= 2048 px long edge, JPEG q~0.85)
  document: <= 25 MB; PDF <= 100 pages; DOCX/TXT extracted text <= 1,500,000 chars
  OCR cap for scanned PDFs: first 40 pages by default; further pages are
         skipped with an ExtractionWarning code "OCR_PAGE_CAP".
  chat message <= 4000 chars; generations/day = 30; chat messages/day = 200
  rate limits: 120 req/min/IP general; 10 req/min/IP on /v1/auth/*

3.7 Polling guidance (frontend)
  Poll GET /v1/jobs/:id every 1.5 s, backing off to 4 s after 30 s; stop on
  succeeded/failed/canceled. After source_processing succeeds, fetch the source
  and SHOW extraction status before offering generation.

4. SETUP, ENVIRONMENT, REALISTIC DEV/TEST WORKFLOW
--------------------------------------------------------------------------------
 - Package manager: Bun. React Native/Metro generally needs a hoisted
   node_modules; if Metro cannot resolve packages, set `[install] linker =
   "hoisted"` in bunfig.toml (check Bun's current docs). Scripts in package.json:
     start (expo start), android, ios, lint (biome lint .), format (biome format
     --write .), check:biome (biome check .), typecheck (tsc --noEmit), test

     jest && expo-doctor).
 - Env: EXPO_PUBLIC_API_URL (e.g. http://192.168.1.20:3000). Provide

   clear in-app configuration error screen if missing/invalid.
   NOTE for docs: `localhost` does NOT work from a physical phone; use the dev
   machine's LAN IP. Android emulator uses http://10.0.2.2:3000; iOS simulator
   can use localhost. Plain-HTTP is acceptable only for development; production
   builds must use HTTPS (document that Android release builds block cleartext).
 - Development with Expo Go (primary workflow): `bun install`, `bunx expo start`,
   scan the QR with Expo Go (same Wi-Fi) or use simulators. Features that work in
   Expo Go IF the installed SDK's Expo Go includes them (verify; write results to
   docs/EXPO-GO-NOTES.md): expo-camera, expo-image-picker, expo-document-picker,
   expo-file-system, expo-image-manipulator, expo-secure-store, expo-localization,
   expo-blur, expo-haptics, expo-crypto, expo-image, @react-native-async-storage,
   @react-native-community/netinfo. For expo-glass-effect and anything else
   native: check the Expo docs for Expo Go support; if unsupported, do NOT make
   the app depend on it; the fallback path (Section 12) must be what runs in Expo
   Go. Document that a development build (`bunx expo run:ios|android` or EAS

7. API LAYER (src/api)
--------------------------------------------------------------------------------
 - client.ts: one Axios instance (baseURL = EXPO_PUBLIC_API_URL + "/v1"; JSON
   default; timeout 20 s; per-call overrides: uploads 180 s, chat 65 s, grading
   35 s). Request interceptor: attach Authorization (access token from memory),
   Accept-Language (UI language), X-Request-Id (uuid). Idempotency-Key: generate
   a uuid ONCE per user action and reuse it on automatic or manual retries of the
   SAME action (store it in the mutation variables / component state), required
   for POST /sources, POST /materials, POST /conversations/:id/messages.
 - Response interceptor: normalize all failures into ApiError { status, code,
   message, retryable, requestId, details } (src/api/errors.ts) following
   contract 3.2; network failures -> code "NETWORK_ERROR" (client-only code),
   timeouts -> "CLIENT_TIMEOUT" (client-only). Map both in i18n.
 - Token refresh: on 401 TOKEN_EXPIRED (or 401 with an expired access token)
   perform a SINGLE-FLIGHT refresh (one shared promise), then retry the original
   request once. If refresh fails with REFRESH_TOKEN_INVALID/REUSED -> clear
   session, route to the welcome/sign-in flow, keep the user informed. Never
   loop.
 - endpoints/*.ts: one typed function per contract endpoint (auth, me, home,
   sources, materials, jobs, conversations, study, meta). Types in types.ts
   mirror contract 3.4 exactly (enums as string-literal unions, nullable fields
   as `T | null`). Runtime-validate nothing heavy; do guard unknown enum values
   defensively in UI (fallback label).
 - queryKeys.ts: central factory (e.g. ['sources', params], ['source', id],
   ['job', id], ['material', id], ['materials', params], ['conversations'],
   ['messages', id], ['home'], ['meta'], ['studySessions', params]).
 - TanStack Query defaults: staleTime 30 s, retry 2 for GET (not for 4xx other
   than 429/408), no retry for mutations by default, refetchOnReconnect on,
   refetchOnWindowFocus mapped to AppState "active" via focusManager, network
   state via onlineManager + NetInfo. Mutations invalidate relevant keys.
 - Job polling hook useJob(jobId): refetchInterval 1500 ms for the first 30 s,
   then 4000 ms; stop when status is terminal; pause while app is backgrounded
   or offline; on `succeeded` invalidate ['source', id]/['materials']/['home'].
   Persist active job ids in memory so leaving/re-entering a screen resumes
   polling; the Home screen also shows `activeJobs` from /v1/home.
 - Pagination: useInfiniteQuery with `nextCursor`.
 - Upload helper: build FormData with `files` parts ({ uri, name, type } objects
   as React Native requires), optional title/language; onUploadProgress drives a
   progress bar; AbortController for cancel; DO NOT set Content-Type manually
   (let the runtime add the multipart boundary; verify behavior with Axios on RN
   and adjust if needed).
